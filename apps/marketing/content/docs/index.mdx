# Put boundaries around production work

Captor runs inside your Node.js application. Declare a resource ceiling, reserve capacity before side effects, record progress after successful work, and verify the outcome. Keep your existing scheduler and database client.

Start with the [quickstart](/docs/getting-started/quickstart), then run the [recovery demo](/docs/getting-started/recovery-demo). No Captor account, database, provider key, or hosted service is required for either.

- [Execution contracts](/docs/execution/contracts): resources, reservations, metrics and deadlines.
- [Backfills and resume](/docs/execution/backfills): batches, durable progress and replay boundaries.
- [Stores and CLI](/docs/execution/stores): inspect local receipts and failures.
- [Adapters](/docs/execution/adapters): bounded fetch calls and Prisma writes.
- [SDK API](/docs/reference/sdk-api): public execution API.
- [Platform receipts](/docs/platform/receipts): optional manual import and inspection.

The product is **Captor**; the npm package is **captar**. The existing OpenAI-compatible runtime remains supported through the [AI compatibility quickstart](/docs/getting-started/ai-quickstart).
